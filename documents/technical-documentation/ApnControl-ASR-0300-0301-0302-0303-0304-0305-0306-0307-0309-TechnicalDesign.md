# APN 管控（ASR-0300/0301/0302/0303/0304/0305/0306/0307/0309）技术设计文档

## 1. 需求概述

| 需求 ID | 功能项 | 需求语义 | 底层机制 |
|---|---|---|---|
| ASR-0300 | 获取系统 APN 配置列表 | 按 mcc + user_editable 分页查询 APN 列表 | `content://telephony/carriers` 查询（平台签名 WRITE_APN_SETTINGS） |
| ASR-0301 | 获取指定 APN 配置 | 按名称获取单个 APN | 同表按 name/apn 查询（**2026-08-13 修正**） |
| ASR-0302 | 添加 APN | 新增 APN（自动补默认字段、simCarrierId） | carriers 表 insert（返回 _id） |
| ASR-0303 | 删除 APN | 删除指定 APN | carriers 表 delete（**2026-08-13 修正 name/apn 匹配**） |
| ASR-0304 | 修改 APN | 更新指定 APN 字段 | carriers 表 update（ContentValues；**2026-08-13 修正参数读取**） |
| ASR-0305 | 激活 APN | 设置/查询首选（preferred）APN | preferapn 表更新（**2026-08-13 修正 id 匹配**） |
| ASR-0306 | 重置 APN | 恢复 carriers 默认配置 | `content://telephony/carriers/restore` delete |
| ASR-0307 | 用户是否可以手动切换模式 | 禁止/允许用户改变移动网络设置 | `DISALLOW_CONFIG_MOBILE_NETWORKS`（与 B12 共用，见 MobileNetworkSettingsRestriction 文档） |
| ASR-0309 | 获取当前激活的 APN 接入点 | 查询当前首选 APN | preferapn 表查询（同 ASR-0305） |

**归属**：「Launcher（MDM）」（平台签名 + WRITE_APN_SETTINGS 签名权限）。

**基线**：目标平台 Android 13（API 33）userdebug，平台签名 + device owner 部署；本机无 SIM 卡（built-in carriers 表仍含 mcc=460 默认配置）。

## 2. 技术选型与可行性核验

| 方案 | 说明 | 结论 |
|---|---|---|
| carriers/preferapn 表直查直写（ContentProvider） | 平台签名 WRITE_APN_SETTINGS（manifest 既有声明）经 `content://telephony/carriers` 操作 | **采用**（ApnManager 引擎） |

**2026-08-13 本批次真机核验并修复 4 处缺陷**：

1. **GetApnConfigByName（ASR-0301）**：原实现仅按 `apn=?` 字段匹配（参数名为 name 实为 apn 值），且缺少防御性 `cursor.getType` 读取（本 ROM schema 部分列 getType 抛异常导致命令整体异常、RESULT null）——修正为 `name=? OR apn=?` 匹配 + 防御性类型读取（与 ApnList 同形制）；
2. **getApnIdByName（ASR-0305）**：同款仅按 apn 字段匹配——修正为 name OR apn；
3. **DeleteApn（ASR-0303）**：同款仅按 apn 字段匹配（按显示名删除返回 0 行）——修正为 name OR apn；
4. **UpdateApn（ASR-0304）**：`Bundle.getParcelable(String, Class)` 在本 ROM 对 ContentValues 抛 NullPointerException——改经 `Bundle.get()` 直取 ContentValues；且 TelephonyProvider 的 update 要求 mcc/mnc/numeric 等字段齐全（测试事件补齐全字段后 updated=1）；
5. **testapp JSON 序列化**：ContentValues 经 binder 到达 testapp 后非 JSON 可序列化（RESULT 显示 null）——TestCommandReceiver 增加 normalize（ContentValues/Map/List 递归转纯 Map）。

**真机核验**：ApnList 返回 built-in carriers（CBNET/CMNET/China Telecom/IMS/MMS 等，mcc=460）；AddApn 返回行 _id；ResetApn（restore URI）返回 1；无 SIM 不影响表操作。

## 3. 命令接口定义

| 命令名 | 参数（Map） | 返回 RESULT | 需求 |
|---|---|---|---|
| `ApnList` | 无 | List\<Map\>（carriers 全字段） | ASR-0300 |
| `GetApnConfigByName` | name（String，必填；name 或 apn 值均可） | ContentValues→Map（无匹配返回 null） | ASR-0301 |
| `AddApn` | name、apn（必填）、mcc、mnc、type（可选） | int（新行 _id；失败 -1） | ASR-0302 |
| `DeleteApn` | name（String，必填；name 或 apn 值均可） | int（删除行数） | ASR-0303 |
| `UpdateApn` | apn（String，必填——匹配的 apn 值）、updateValues（ContentValues，必填） | int（更新行数） | ASR-0304 |
| `SetPreferredApn` | name（String，必填；name 或 apn 值均可） | Boolean（id 解析成功且更新>0） | ASR-0305 |
| `GetPreferredApn` | 无 | String（当前首选 apn 值；无则 null） | ASR-0305/0309 |
| `ResetApn` | 无 | int（restore 删除行数） | ASR-0306 |
| `DisallowConfigMobileNetworks`/`IsDisallowConfigMobileNetworks` | disallow（Boolean） | Boolean | ASR-0307（见 B12 文档） |

**调用示例**：

```java
Map<String, Object> p = new HashMap<>();
p.put("name", "SyriusTest");
p.put("apn", "test.apn");
p.put("mcc", "460");
p.put("mnc", "01");
Map result = api.onEvent("AddApn", p);
// {"RESULT":3623}

Map result2 = api.onEvent("GetApnConfigByName", p);
// {"RESULT":{...,"name":"SyriusTest","apn":"test.apn","_id":3623,...}}
```

## 5. 执行逻辑

```
ApnList(): carriers 表按 mcc + user_editable=1 分页查询 → List<Map>
GetApnConfigByName(name): name=? OR apn=? 单行查询 → ContentValues（防御性 getType）
AddApn(name, apn, mcc, mnc, type): 默认字段+simCarrierId 补齐 → insert → 返回 _id
DeleteApn(name): name=? OR apn=? 删除 → 返回行数
UpdateApn(apn, updateValues): apn=? 匹配 → update（values 需含 mcc/mnc/numeric 等字段，真机核验）→ 行数
SetPreferredApn(name): getApnIdByName（name OR apn）→ preferapn 表 apn_id 更新
GetPreferredApn(): preferapn 表查询 → apn 值
ResetApn(): carriers/restore delete → 行数
```

**安全设计**：WRITE_APN_SETTINGS 签名权限平台签名授予；调用方经 ApiBinder 门禁；命令仅操作 carriers/preferapn 表。

## 6. 权限与归属

- 平台签名 WRITE_APN_SETTINGS（manifest 既有声明）经 ContentProvider 操作；TelephonyManager.getSimCarrierId（READ_PHONE_STATE 既有）；
- testapp：无新增权限；无 ROM 侧代码改动，无 root 依赖。

## 7. 边界与异常处理

| 场景 | 处理 |
|---|---|
| 缺参 | testapp 侧返回 missing parameter，不 crash |
| 无匹配（查询/删除/更新） | 返回 null/0（如实） |
| getType 异常（本 ROM schema） | 防御性读取（FIELD_TYPE_NULL 兜底，2026-08-13 修复） |
| ContentValues 参数读取 | Bundle.get 直取（getParcelable(String,Class) 本 ROM NPE，2026-08-13 修复） |
| update 字段不全 | TelephonyProvider 拒绝 → updated=-1 如实（测试事件补齐 mcc/mnc/numeric/name 后成功） |
| 无 SIM | 表操作不受影响（built-in carriers 存在，真机核验）；APN 实际生效需 SIM（硬件受限说明） |
| ResetApn | 恢复 carriers 默认（用户新增行被清除——测试顺序：重置放删除前/后按用例设计） |
