# 热点/网络共享管控（ASR-0167/0169/0398/0399/0400/0401/0402/0403/0404/0405）技术设计文档

## 1. 需求概述

| 需求 ID | 功能项 | 需求语义 | 实现机制 |
|---|---|---|---|
| ASR-0167 | WiFi个人热点 | 禁用/启用 WiFi 个人热点 | `SetHotspotEnabled`/`IsHotspotEnabled`：反射 `TetheringManager.startTethering(TETHERING_WIFI)/stopTethering(TETHERING_WIFI)` 一次性开关 + 查询，与 ASR-0169 共用命令（同 WLAN ASR-0140/0142 模式） |
| ASR-0169 | WiFi个人热点 | 打开/关闭个人热点 | 同 ASR-0167 引擎（`SetHotspotEnabled`/`IsHotspotEnabled`） |
| ASR-0398 | 网络共享 | 获取/设置 是否禁用网络共享 | `SetTetheringDisabled`/`IsTetheringDisabled`：**总开关**——禁用=停止全部三种共享（WIFI/USB/蓝牙）并置"禁止"标志，10 秒纠正器持续关闭任何被重新打开的共享；启用=清除总开关 |
| ASR-0399 | 网络共享 | 获取/设置 是否禁止 USB 共享网络 | `SetUsbTetheringForbidden`/`IsUsbTetheringForbidden`：USB 类型禁止标志 + 10 秒纠正器（用户/应用打开后被重新关闭） |
| ASR-0400 | 网络共享 | 禁止/允许 用户修改 USB 共享网络 Settings | 复用既有 `SetUserConfigTetheringDisabled`/`IsUserConfigTetheringDisabled`（device owner `DISALLOW_CONFIG_TETHERING`，ASR-0168 引擎；AOSP 13 无按类型区分的设置页限制，该限制整页生效） |
| ASR-0401 | 网络共享 | 查询/静默打开/静默关闭 USB 共享网络 | `SetUsbTetheringEnabled`/`IsUsbTetheringEnabled`：`startTethering(TETHERING_USB)`（静默，无 provisioning 弹窗）/`stopTethering` + 查询 |
| ASR-0402 | 网络共享 | 获取/设置 是否禁止 WLAN 共享网络 | `SetWifiTetheringForbidden`/`IsWifiTetheringForbidden`：WIFI 类型禁止标志 + 10 秒纠正器 |
| ASR-0403 | 网络共享 | 获取/设置 禁止蓝牙共享网络 | `SetBluetoothTetheringForbidden`/`IsBluetoothTetheringForbidden`：蓝牙类型禁止标志 + 10 秒纠正器 |
| ASR-0404 | 网络共享 | 获取/静默打开/静默关闭蓝牙共享网络 | `SetBluetoothTetheringEnabled`/`IsBluetoothTetheringEnabled`：`startTethering(TETHERING_BLUETOOTH)`（静默）/`stopTethering` + 查询 |
| ASR-0405 | 网络共享 | 禁止/允许 用户修改蓝牙共享网络 Settings | 同 ASR-0400：复用 `SetUserConfigTetheringDisabled`/`IsUserConfigTetheringDisabled`（ASR-0168 引擎） |

**归属**：ASR-0167/0169/0398/0399/0401/0402/0403/0404 落地为**平台签名应用调用 @SystemApi 系统接口**（`TetheringManager` 自 API 29 起为 @SystemApi，**不在公开 SDK 中**（2026-08-05 对 API 33 android.jar 核验：无 `TetheringManager`/`TetheringRequest`/`StartTetheringCallback` 类、`ConnectivityManager` 无 `getTetheringManager`），故全部经反射调用，配合 `TETHER_PRIVILEGED`/`NETWORK_SETTINGS` 签名权限（平台签名 uid=1000 自动授予）；ASR-0400/0405 为 device owner 公开 `DISALLOW_CONFIG_TETHERING` 用户限制（Launcher（MDM））。无 ROM 侧代码改动。

> 归属口径调整（2026-08-05，本批次）：ASR-0167/0398/0399/0402/0403 原归属「Launcher（MDM）」，经公开 SDK 核验（API 33 android.jar 无 TetheringManager、WifiManager.isWifiApEnabled 亦不在公开 SDK 中）确认必须经平台签名调用 @SystemApi，归属调整为「Launcher（MDM）+ 系统 API」（与 ASR-0169 一致）。

## 2. 技术选型与可行性核验

### 2.1 公开 SDK 与系统接口核验（2026-08-05）

| 核验项 | 结果 |
|---|---|
| `TetheringManager`（API 29+ @SystemApi） | **不在公开 SDK**（API 33 android.jar 无此类，2026-08-05 javap 核验）；实例经 `Context.getSystemService("tethering")`（AOSP 13 SystemServiceRegistry 注册）或反射 `ConnectivityManager.getTetheringManager()` 获取 |
| `TetheringManager.startTethering` | AOSP 13 存在两签名：`(int, boolean showProvisioningUi, StartTetheringCallback)`（@Deprecated 31，showProvisioningUi=false 即静默、跳过 provisioning 弹窗）与 `(int, Executor, StartTetheringCallback)`；**优先反射 `(int, boolean, callback)` 静默变体**，失败回退 Executor 变体 |
| `TetheringManager.stopTethering(int)` | @SystemApi，直接反射调用（无回调，写后轮询读回核对） |
| `StartTetheringCallback` | @SystemApi 接口（`android.net.TetheringManager$StartTetheringCallback`，`onTetheringStarted()`/`onTetheringFailed(int)`），以 `java.lang.reflect.Proxy` 动态代理实现，`CountDownLatch` 等待回调（15s 超时防悬死） |
| 状态查询 | WiFi 主通道：反射 `WifiManager.isWifiApEnabled()`（@SystemApi，本 ROM 保留）；USB/蓝牙：`getTetheredIfaces()`（String[]）+ `getTetheringType(iface)`（AOSP 13 存在时优先）+ `getTetherable(Usb|Wifi|Bluetooth)Regexs()` 正则匹配 + 硬编码兜底（rndis/usb、bt-pan、wlan/ap） |
| 权限 | `TetheringService` 对 start/stop/查询执行 `enforceTetherAccessPermission`（NETWORK_SETTINGS 或 TETHER_PRIVILEGED，均 signature 级）；本批次 manifest 新增声明 `NETWORK_SETTINGS` + `TETHER_PRIVILEGED`，平台签名 uid=1000 自动授予（与 NFC 批次 `WRITE_NFC_SETTINGS` 同模式） |
| 蓝牙共享前置 | 蓝牙共享需蓝牙已开启；`startTethering(TETHERING_BLUETOOTH)` 在蓝牙关闭/无蓝牙硬件时框架回调 onTetheringFailed，命令如实上报 |

### 2.2 语义设计（与既有批次一致的模式）

- **一次性开关（ASR-0167/0169/0401/0404）**：`enabled=true` → `startTethering(type)`（静默）；`enabled=false` → `stopTethering(type)`；写后轮询读回核对一致才 `success=true`（与 WLAN ASR-0140/0142、移动数据 ASR-0275/0276 同模式）；
- **禁止类策略（ASR-0398/0399/0402/0403）**：`forbidden=true` 持久化标志 + 立即停止该类型共享 + 启动 10 秒周期纠正器；纠正器 tick 时若该类型处于活动态（用户/应用在 Settings 打开）则重新 `stopTethering(type)`；`false` 停止纠正并清标志；
- **总开关（ASR-0398）**：`disabled=true` 隐含三种类型全部禁止（WIFI/USB/蓝牙），并立即停止全部当前共享；`disabled=false` 清除总开关后，各类型自身的禁止标志仍生效；
- **持久化**：四个标志存于 SharedPreferences `tethering_policy`（tetheringDisabled/wifiForbidden/usbForbidden/btForbidden），进程重启（`ApiService.onCreate`）与开机（`BootCompletedReceiver`）经 `syncPolicy` 重新武装并立即纠正一次。

## 3. 命令接口定义（SystemApiInterface.onEvent）

### 3.1 新增命令（本批次，14 条；ASR-0400/0405 复用既有命令）

| 命令名 | 参数（Map） | 返回 RESULT | 需求 |
|---|---|---|---|
| `SetHotspotEnabled` | enabled（Boolean，必填） | Map：{success, supported, hotspot, hotspotActive, wifiTethering, usbTethering, bluetoothTethering, tetheringDisabled, wifiForbidden, usbForbidden, bluetoothForbidden} 或 {error} | ASR-0167/0169 |
| `IsHotspotEnabled` | 无 | 同上（含 wifiTethering 等状态与四个标志） | ASR-0167/0169 |
| `SetUsbTetheringEnabled` | enabled（Boolean，必填） | 同上（usbTethering/usbTetheringActive） | ASR-0401 |
| `IsUsbTetheringEnabled` | 无 | 同上 | ASR-0401 |
| `SetBluetoothTetheringEnabled` | enabled（Boolean，必填） | 同上（bluetoothTethering/bluetoothTetheringActive） | ASR-0404 |
| `IsBluetoothTetheringEnabled` | 无 | 同上 | ASR-0404 |
| `SetTetheringDisabled` | disabled（Boolean，必填） | Map：{success, supported, disabled, wifiTethering, usbTethering, bluetoothTethering, wifiForbidden, usbForbidden, bluetoothForbidden} 或 {error} | ASR-0398 |
| `IsTetheringDisabled` | 无 | 同上（含 disabled） | ASR-0398 |
| `SetUsbTetheringForbidden` | forbidden（Boolean，必填） | Map：{success, supported, forbidden, type, wifiTethering, usbTethering, bluetoothTethering, tetheringDisabled, wifiForbidden, usbForbidden, bluetoothForbidden} | ASR-0399 |
| `IsUsbTetheringForbidden` | 无 | 同上（含 forbidden） | ASR-0399 |
| `SetWifiTetheringForbidden` | forbidden（Boolean，必填） | 同上 | ASR-0402 |
| `IsWifiTetheringForbidden` | 无 | 同上 | ASR-0402 |
| `SetBluetoothTetheringForbidden` | forbidden（Boolean，必填） | 同上 | ASR-0403 |
| `IsBluetoothTetheringForbidden` | 无 | 同上 | ASR-0403 |
| `SetUserConfigTetheringDisabled`（复用，ASR-0168 批次） | disabled（Boolean，必填） | Map：{success, disabled, restriction=no_config_tethering} | ASR-0400/0405 |
| `IsUserConfigTetheringDisabled`（复用） | 无 | 同上 | ASR-0400/0405 |

**字段说明**：`wifiTethering`/`usbTethering`/`bluetoothTethering` 为三种共享类型的实时活动态（WiFi 经 `WifiManager.isWifiApEnabled`，USB/蓝牙经 tethered ifaces 匹配）；`tetheringDisabled`/`wifiForbidden`/`usbForbidden`/`bluetoothForbidden` 为四个持久化策略标志；Set 类命令在写后轮询读回核对，不一致时 `success=false` + error（含期望态/实际态/callResult），如实上报不误报成功。

**Set 类命令返回结构**（以 SetHotspotEnabled enabled=true 为例）：

```
{success:boolean, supported:true, hotspot:true, hotspotActive:true,
 wifiTethering:true, usbTethering:false, bluetoothTethering:false,
 tetheringDisabled:false, wifiForbidden:false, usbForbidden:false, bluetoothForbidden:false}
# startTethering 回调 onTetheringStarted 且读回 wifiTethering=true 才 success=true
```

## 5. 执行逻辑

```
SetHotspotEnabled / SetUsbTetheringEnabled / SetBluetoothTetheringEnabled(enabled):
  1. 参数校验（缺 enabled → {error}）
  2. 获取 TetheringManager（getSystemService("tethering") → 回退反射 ConnectivityManager.getTetheringManager()；不可用 → {success:false, supported:false, error}）
  3. enabled=true：反射 startTethering(type, false, 代理回调)（回退 Executor 变体），latch 等待回调（15s 超时）；enabled=false：反射 stopTethering(type)
  4. 轮询读回该类型状态（开≤15s / 关≤8s），期望==实际才 success=true
  5. 附报三种类型实时状态与四个策略标志；返回 Map

SetTetheringDisabled(disabled)（ASR-0398 总开关）:
  1. 参数校验（缺 disabled → {error}）
  2. 持久化 tetheringDisabled 标志
  3. true：立即停止全部三种活动共享；启动 10s 纠正器
  4. false：清标志；无其他活动标志则停止纠正器
  5. 返回 {success, supported, disabled, 三种类型状态, 各禁止标志}

SetUsbTetheringForbidden / SetWifiTetheringForbidden / SetBluetoothTetheringForbidden(forbidden):
  1. 参数校验（缺 forbidden → {error}）
  2. 持久化该类型禁止标志
  3. true：该类型当前活动则立即停止；启动 10s 纠正器
  4. false：清标志；无其他活动标志则停止纠正器
  5. 返回 {success, supported, forbidden, type, 三种类型状态, 各禁止标志}

纠正器 tick（10s，单线程池）:
  1. 无任何活动标志 → 停止纠正器
  2. master=tetheringDisabled；对 WIFI/USB/蓝牙 各类型：isForbidden = master || 类型标志
  3. 类型禁止 且 该类型当前活动 → 重新 stopTethering(type)（日志记录 was/ok）

Is* 查询: 读取三种类型实时状态与四个标志如实返回

ASR-0400/0405（复用）：SetUserConfigTetheringDisabled/IsUserConfigTetheringDisabled
  → WifiControlPolicyManager.setRestriction(DISALLOW_CONFIG_TETHERING)（device owner，见 WlanControl 设计文档）
```

**安全设计**：本批命令参数全部为布尔值，无字符串进入 shell / 系统命令，无命令注入面；反射方法名均为代码内常量；仅调用系统既有 @SystemApi 接口（TetheringManager，NETWORK_SETTINGS/TETHER_PRIVILEGED 签名权限），无权限面扩大、无 ROM 改动；`CountDownLatch.await` 带超时，回调异常不悬死。

## 6. 权限与归属

- `NETWORK_SETTINGS` / `TETHER_PRIVILEGED`（signature|privileged）：本批次在 manifest 新增声明，平台签名 Launcher（uid=1000，sharedUserId=android.uid.system）安装时自动授予（与 NFC 批次 `WRITE_NFC_SETTINGS` 同模式；`dumpsys package com.hmdm.launcher` 可核对 granted=true）；
- TetheringService 对 start/stop/iface 查询执行 `enforceTetherAccessPermission`（NETWORK_SETTINGS 或 TETHER_PRIVILEGED），平台签名 uid=1000 放行；
- `WifiManager.isWifiApEnabled`（@SystemApi）反射调用，`ACCESS_WIFI_STATE`（既有）覆盖；
- ASR-0400/0405：device owner `DISALLOW_CONFIG_TETHERING`（公开 DPM API，无需 uses-policy 声明，见 system_configurations.md 第 2 节）；
- 无 ROM 侧代码改动，无 root 依赖；不修改 AIDL / lib 模块；testapp 无需新增权限（命令在 Launcher 进程执行）；不修改 `device_admin.xml`，无需重启 framework。

## 7. 边界与异常处理

| 场景 | 处理 |
|---|---|
| 缺 enabled / disabled / forbidden 参数 | 命令返回 {error："missing parameter: ..."}，不 crash；testapp 侧同样拦截 |
| TetheringManager 服务不可用（getSystemService 与 ConnectivityManager.getTetheringManager 均失败） | 命令返回 {success:false, supported:false, error:"tethering service unavailable"}，不 crash |
| startTethering 回调 onTetheringFailed(reason) | 记录 reason 日志，success=false + error（"not started"），如实上报 |
| startTethering 15s 无回调（框架异常/悬死） | latch 超时返回 success=false + error，不悬死；startTethering 为异步启动，读回状态仍可成功 |
| 蓝牙共享前置（蓝牙关闭/无蓝牙硬件） | 框架回调 onTetheringFailed，success=false 如实上报；查询返回实际活动态 |
| 一次性开关与禁止策略同时活动 | 开关打开被纠正器在 10s 内关闭（禁止优先，属预期策略行为，文档明示） |
| 禁止纠正器运行时用户/应用打开共享 | 10 秒内被重新关闭（tick 间隔 10s）；`forbidden=false` 停止纠正并保持用户状态 |
| 总开关与类型禁止同时活动 | 总开关隐含全部类型禁止；`disabled=false` 后各类型自身标志仍生效 |
| 进程被杀 / 重启 / 开机 | 四个标志持久化于 SharedPreferences `tethering_policy`；ApiService.onCreate 与 BootCompletedReceiver 经 syncPolicy 重新武装并立即纠正一次 |
| 测试结束状态恢复 | 四个标志均须置 false 清空（含总开关）；`tethering_policy.xml` 留空标志（无残留策略），共享状态与测试前一致 |

## 9. 与既有批次的关系

- 与移动数据（ASR-0275~0279）、NFC（ASR-0315~0317）、飞行模式（ASR-0319~0321）共用「Set/Is 共用引擎 + 10 秒纠正器 + SharedPreferences 持久化 + ApiService/BootCompletedReceiver 重新武装」模式；本批次纠正器按**类型维度**（WIFI/USB/蓝牙）解析禁止目标，并引入**总开关**（ASR-0398，隐含全部类型）语义；
- 一次性开关语义与 WLAN ASR-0140/0142（禁用/启用=打开/关闭）一致；
- ASR-0400/0405 复用 WlanControl 批次 ASR-0168 的 `DISALLOW_CONFIG_TETHERING` 引擎（`Set/IsUserConfigTetheringDisabled`）；
- 命令注册、testapp 事件目录、文档体系与既有批次一致；无 AIDL/lib 模块改动。
